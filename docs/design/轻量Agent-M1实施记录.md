# 轻量 Agent M1 实施记录

日期：2026-09-17。用户已授权开始执行设计；本次范围为 M1，未执行 M2～M5，未提交或推送 Git，未修改本地 `.env`，未启用 Agent。

## 已实现

- `rag_pipeline.prepare_evidence` 提供检索和证据判定，不生成答案、不读取长期记忆；原 RAG 包装入口保留。
- Agent 路径按服务器提供的可读知识库检索，并对编排/主题候选执行发布状态终检。
- 请求上下文记录知识库、子查询、主题、关键词、发布终检及证据核验失败；区分无候选、证据不足、服务失败和部分失败。
- 千问原生工具消息接口使用 `result_format=message`，校验工具调用结构、ID，并回传匹配的 `tool_call_id`。错误响应不直接公开供应商原始内容。
- 注册三个白名单能力：`get_current_datetime`、`search_knowledge`、`request_clarification`；禁止额外参数、模型自选身份/知识库以及未知工具。
- 日期工具使用服务器时钟和 IANA 时区；支持可注入时钟测试，无效时区要求更正，不静默回退。
- 每请求最多五轮决策、八次调用；重复调用按请求内缓存复用，校验失败同样消耗预算。
- 准备默认总限时 30 秒；跨线程传播剩余预算，收紧内部模型请求及重试等待；全进程至多八个在途准备工作，超时停止等待、迟到结果丢弃，后台实际结束后才释放槽位。
- 模型输出“文本 + 调用”时不展示未验证文本；零工具事实文本也不直接作为答案。工具结果分类进入一次最终生成。
- 聊天 API 按 `AGENT_ENABLED` 选择入口；JSON/SSE 增加可选 `tool_sources`，SSE 支持公开 `status`。原入口关闭开关时保持响应兼容。
- SSE 等待期间检查断连并设置取消信号；不再启动新工具，不保存半条 assistant；意外缺少 done 的流返回 error。
- 为避免工具结果污染长期记忆，M1 暂停所有 Agent 回合的长期提取；短期对话仍保存。
