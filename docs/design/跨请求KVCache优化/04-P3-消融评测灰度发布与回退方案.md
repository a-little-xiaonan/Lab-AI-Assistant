# P3：消融评测、灰度发布与回退方案

> 状态：讨论稿，依赖 P0、P1 通过；P2 通过后才可纳入分级资料模板。
> 适用范围：高频 FAQ 模板与 Context Cache 的效果证明、线上风险控制和持续迭代。

## 1. 目标

用控制变量区分“FAQ 模板绕过检索”的收益与“KV Cache 减少 Prefill”的收益，避免只因路径变短就把所有加速归因于缓存。质量与安全未达标时自动或人工关闭该分支，继续使用已有 RAG。

## 2. 评测数据集

在 `docs/eval/recruitment-qa.json` 的基础上新增独立分区 `faq_cache_holdout`，每个已启用模板至少包含：

- 10 条标准问法、口语表达与同义改写；
- 5 条近似但不应命中的问题；
- 5 条资料不足、过期信息或越权问题；
- 对应的标准要点、允许来源、预期模板 code 或“必须回退 RAG”标签。

缓存优化调参使用 `faq_cache_dev`；上线结论必须使用未参与别名、规则和 Prompt 调整的 `faq_cache_holdout`。任何失败样本不得从固定集删除。

## 3. 四组消融实验

| 组别 | FAQ 路由 | 固定证据卡 | Provider Cache | 用途 |
| --- | --- | --- | --- | --- |
| A | 否 | 否 | 否 | 现有 RAG 基线 |
| B | 是 | 是 | 否 | 衡量模板路径与跳过检索的影响 |
| C | 是 | 是 | 是，冷启动 | 衡量创建缓存的成本 |
| D | 是 | 是 | 是，热命中 | 衡量缓存带来的真实收益 |

每组使用相同模型、模型参数、知识库快照、题集和并发条件。C 与 D 需在供应商缓存有效窗口内执行；D 的前缀 hash 必须等于 C，才可视作同一缓存对象。

## 4. 指标定义

### 质量与安全

- 模板路由精确率、召回率与误路由率；
- 回答要点覆盖率；
- 引用一致性与引用来源精确率；
- 无答案拒答准确率；
- 资料更新后旧模板误用次数；
- 越权模板命中次数。

### 性能与成本

```text
route_ms                鉴权后的 FAQ 匹配与模板校验耗时
retrieval_ms            现有检索 + 重排 + 证据门槛耗时
prefill_proxy_ms        从模型调用开始到首个文本增量的近似指标
ttft_ms                 HTTP 请求接收至首个 SSE delta
end_to_end_ms           HTTP 请求接收至 done
input_tokens
cached_tokens
cache_creation_tokens
cache_hit
```

对外报告使用 P50/P95、样本数、模型、知识库快照与缓存命中率。不能仅报告平均耗时或只选缓存命中的样本。

## 5. 线上灰度

灰度开关建议：

```text
FAQ_TEMPLATE_ENABLED=false
FAQ_TEMPLATE_PUBLIC_ONLY=true
CONTEXT_CACHE_ENABLED=false
FAQ_TEMPLATE_ROLLOUT_PERCENT=0
```

发布顺序：

1. 测试环境运行 POC 与四组消融；
2. 生产环境仅对管理员可见的验证流量启用；
3. 公开模板按稳定的 request_id hash 灰度 5% → 25% → 50% → 100%；
4. 每个阶段至少覆盖一个完整缓存 TTL、正常高峰和文档发布事件；
5. P2 通过前保持 `PUBLIC_ONLY=true`。

日志只记录模板 code、版本、快照 hash、耗时和 Token 指标，不记录用户问题原文、证据正文或完整回答。

## 6. 上线门槛

建议将下列条件作为进入下一灰度比例的门槛：

- 模板路径质量指标不低于 A 组基线；
- 误路由率、越权命中、失效模板命中均为 0；
- D 组在足够样本中有正数 `cached_tokens`；
- D 组 TTFT P50 改善达到预设阈值，且 P95 不恶化；
- 结合缓存创建成本后，单位有效问答的输入 Token 成本不高于 B 组；
- 缓存 adapter、模板校验和回退异常均可追踪。

TTFT 的具体目标应在 P0 基线测得后再设定。当前项目没有历史 TTFT 数据，因此不得直接承诺“2 秒以内”。

## 7. 回退与故障处理

| 现象 | 处理 |
| --- | --- |
| Provider 缓存不可用或响应字段缺失 | 关闭 `CONTEXT_CACHE_ENABLED`，保留模板或直接回退 RAG |
| 模板回答质量下降 | 停用对应 template code，其他模板不受影响 |
| 资料发布后发现模板 stale | 将模板设为 `disabled`，重新审核证据后发布新版本 |
| 权限或来源泄露 | 立即关闭 `FAQ_TEMPLATE_ENABLED`，审计受影响请求并按安全事件处理 |
| TTFT/P95 恶化 | 回退灰度比例并比较 B、C、D 组指标定位原因 |

所有开关默认关闭；关闭后聊天接口仍遵循当前 intent router、RAG、证据门槛和 SSE 行为，确保该优化是可逆变更。

## 8. 交付物

- POC 报告：模型/协议、缓存字段、样本与冷/热对比；
- 已审核 FAQ 模板、证据清单与快照；
- 消融评测报告与机器可读原始指标；
- 灰度记录、异常处理记录与最终开关状态；
- 简历/答辩可引用的结果口径，例如“在 N 条 FAQ holdout、X% 缓存命中率下，TTFT P50 从 A 降至 B”。
