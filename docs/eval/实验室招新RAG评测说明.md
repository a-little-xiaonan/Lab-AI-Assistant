# 实验室招新 RAG 评测说明

> **评测对象**：`实验室招新公开资料` 知识库
> **样例文件**：`docs/eval/recruitment-qa.json`
> **执行脚本**：`backend/scripts/evaluation/eval_recruitment.py`
> **结果目录**：`data/eval/`（本地运行数据，不提交 Git）

## 1. 样例集组成

固定样例集共 50 题，避免只挑系统擅长的问题：

| 类型 | 数量 | 目的 |
| --- | ---: | --- |
| 事实题 | 25 | 检查实验室、招新、项目与技术资料的直接召回 |
| 口语改写题 | 10 | 检查 Query Rewrite、术语映射和口语表达适配 |
| 多要点题 | 5 | 检查复杂问题是否覆盖多个事实点 |
| 无答案题 | 10 | 检查系统能否拒绝回答资料中不存在或不应公开的信息 |

有答案题必须配置 `expected_sources` 和 `expected_points`；无答案题必须由人工确认公开知识库中不存在明确答案。评测标签只用于计算指标，不能传给检索器或回答模型。

## 2. 指标定义

- **Recall@5**：前 5 个最终证据片段中是否至少出现一个标准来源；衡量能否召回答案。
- **MRR**：第一个标准来源排名的倒数均值；越接近 1，正确资料越靠前。
- **有效来源精确率**：最终证据片段中属于标准来源的比例；衡量上下文噪声。
- **回答要点覆盖率**：最终回答命中的标准事实点比例；只在完整回答模式计算。
- **证据门槛准确率**：有答案题被放行、无答案题被拒绝的总体比例。
- **无答案误放行率**：资料没有答案时仍把候选交给回答模型的比例；该值越低越好。
- **有答案误拒率**：资料存在答案但被门槛拒绝的比例；该值越低越好。
- **无答案拒答准确率**：完整回答是否明确告知知识库未找到，而不是用常识补答。
- **灰区核验调用率**：需要额外调用 LLM 判断证据充分性的题目比例，用于观察成本。
- **平均/P95 延迟**：分别记录检索和端到端耗时；P95 反映慢请求体验。

## 3. 证据门槛设计

初版仅使用余弦相似度或词面覆盖率。50 题检索结果显示，电话号码、补贴、名单等无答案问题仍能召回主题接近的实验室资料，10 道无答案题全部被误放行。这说明“内容与实验室相关”不等于“内容包含所问答案”。

当前采用三级门槛：

```text
候选片段
  → DashScope Rerank 相关度
       ≥ 0.22：直接放行
       < 0.15：直接拒答
       0.15～0.22：LLM 严格核验证据是否明确包含答案
```

灰区核验只输出 `answerable` 和支持片段编号，不生成答案。调用失败时默认保守拒答；纯向量模式则回退到余弦相似度和词面规则。

这些阈值是当前资料和 `gte-rerank-v2` 下的工程标定值，不是通用概率。更换文档、Embedding 或 Rerank 模型后必须重新运行固定样例集。

## 5. 执行方式

只测检索和证据门槛：

```bash
cd backend
../.venv/bin/python scripts/evaluation/eval_recruitment.py --mode retrieval
```

测完整回答、要点覆盖和拒答：

```bash
cd backend
../.venv/bin/python scripts/evaluation/eval_recruitment.py --mode full
```

只重跑指定题目：

```bash
../.venv/bin/python scripts/evaluation/eval_recruitment.py \
  --mode retrieval --ids F01,F02,N01,N02
```

完整模式会产生真实模型调用费用。运行前应确认 API Key、数据库、ChromaDB 与知识库版本一致，并记录 Git 版本和配置快照。

## 6. 防止指标失真

- 不删除系统答错的固定样例，只能修正经人工确认的错误标签；
- 校准集与最终验证集分开记录，不能把调参样例称为盲测；
- 评测前固定知识库文档版本、模型名、Chunk 参数和开关；
- 多次运行报告全部保留，禁止只展示最高的一次；
- 简历上的数字写明样本规模和指标口径，例如“50 道内部固定问答集上的 Recall@5”；
- 当前样例规模较小，结果只表示该实验室招新资料集，不表示通用 RAG 能力。
