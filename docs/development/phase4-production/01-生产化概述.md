## 2. 各项简述（仅规划要点）

### 2.1 用户认证与权限
- FastAPI OAuth2 + JWT，登录/刷新接口；前端登录页 + token 存储（Pinia + localStorage）
- 路由鉴权依赖（`Depends(get_current_user)`），知识库按用户隔离
- 当前无认证是 MVP 预期内的取舍（Phase 1-07 已注明），多用户使用前必须落地

### 2.2 日志与监控
- 结构化日志（structlog 或 logging + JSON formatter），请求 ID 贯穿全链路
- 关键指标：请求耗时、检索耗时、LLM 调用次数/失败率、token 用量 → 扩展 `/api/stats`
- 可选接入 Prometheus + Grafana（本地单机场景非必须）

### 2.3 性能优化
- 批量 Embedding 并行化（多批次并发，控制 QPS 与计费）
- 检索结果 LRU 缓存（相同/相似查询命中）、热点文档预加载
- 文档处理异步化升级（asyncio 队列或 Celery，当前 BackgroundTasks 升级替换）

### 2.4 Docker 部署
- 后端 Dockerfile（瘦身：slim 镜像、分层缓存）+ 前端 nginx 静态托管镜像
- `docker-compose.yml`：环境变量注入、`data/` 卷挂载、SSE 反向代理需关闭缓冲（呼应 Phase 2-01 风险）

### 2.5 API 限流与错误处理
- 全局限流中间件（slowapi 等）：按 IP / 用户限流（LLM 调用成本是主要限流动机）
- 统一错误结构（`{detail: {code, message}}`）覆盖 429 / 5xx；重试与备用模型切换收口（Phase 1-03 已铺垫）
