## 1. 目标与范围

跨会话持久化记忆：每轮对话后 LLM 提取有长期价值的信息，按置信度过滤后存入 ChromaDB（memory collection）；提问时召回相关记忆拼入 prompt。实现对齐 §7.3 伪代码。

## 2. 任务拆解

- [ ] `app/memory/long_term.py`（按 §7.3 实现）：
  - `MEMORY_TYPES = {user_preference, key_fact, faq_pair, entity}`（四类，含中文说明）
  - `extract_and_store(session_id, messages)`：
    - prompt 要求返回 JSON 数组 `[{type, content, confidence}]`
    - 仅 `confidence > 0.7`（配置 `MEMORY_CONFIDENCE_THRESHOLD`）的条目入库
  - `recall(query, session_id, top_k=3)`：向量召回，`where={"session_id": ...}`（对齐 §7.3 伪代码）
- [ ] 存储设计（§5）：collection 名 `kb_{kb_id}_memory` 或全局 `memory`（**建议按 kb 隔离**，与 docs collection 一致；实现时二选一并在文档记录）
  - 元数据：`{type, session_id, timestamp, kb_id}`
- [ ] `memory_manager` 接入：每轮对话后异步调用 `extract_and_store`（不阻塞回答）；`build_prompt` 增加「相关记忆」段（对齐 §7.4 第 2 步，位于检索结果之后、历史之前）
- [ ] 去重与防膨胀：同 session 相同内容重复提取 → 覆盖或跳过（按内容 hash）；`recall top_k=3` 截断召回规模
- [ ] 记忆清理接口（可选）：`DELETE /api/memory/{session_id}`（清某会话记忆），前端设置页入口（Phase 3-04 可选）

## 3. 设计要点

- **异步提取**：提取是额外 LLM 调用（每轮一次），放后台任务执行；提取失败仅记日志，不影响主回答链路
- **置信度阈值是唯一防线**：`confidence > 0.7` 过滤低质量记忆（§7.3 约定）；阈值可从配置调，记忆噪声大就调高
- **prompt 要求**（对齐 §7.3）：「仅提取非显而易见的、有长期价值的信息」—— 过滤常识与一次性闲聊
- **隐私边界**：记忆含用户个人信息（偏好/实体），必须提供清理入口，并在前端注明"记忆可清除"（设计文档未提，属实现补充，注意与文档保持一致口径）
- 与短期记忆分工（呼应 Phase 2-03）：短期是上下文连续性，长期是事实沉淀；长期记忆在**每个新会话**都会召回

## 5. 验收标准

- [ ] 会话 A 中告知「以后都用中文简洁回答」（或类似偏好）→ 会话 B 提问时回答风格体现该偏好（recall 命中并进 prompt）
- [ ] 提取结果 JSON 解析失败 / confidence 低 → 不入库，链路无异常
- [ ] 不同 session 的记忆召回互不串扰（`where` 过滤生效）
- [ ] 记忆清理接口可用，清理后召回为空
- [ ] 提取的 LLM 调用在异步路径：主回答延迟无明显增加

## 6. 风险与注意事项

- **记忆噪声累积**：错误记忆会长期误导回答 —— 置信度阈值 + 清理入口 + （可选）记忆展示与确认机制；上线后观察召回内容质量再调阈值
- **隐私合规**：记忆存储用户个人信息，属敏感数据；MVP 是本地单用户场景风险可控，多用户（Phase 4 认证）时必须按用户隔离并支持清除
- **成本**：每轮多一次 LLM 提取调用，QPS 与计费翻倍风险 —— 可改为「每 N 轮提取一次」或「仅关键对话提取」（配置开关）
- 记忆与知识库检索的拼装顺序影响模型权重：记忆段放在检索之后、历史之前（§7.4），顺序调整需重跑样例集验证
