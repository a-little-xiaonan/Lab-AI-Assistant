## 1. 目标与范围

知识库与文档的管理 UI：知识库卡片列表、新建/删除、文档上传与状态展示、删除/重新索引操作、统计信息。布局对齐 §9.2。

## 2. 任务拆解

- [x] `src/views/KnowledgeBase.vue`：知识库卡片列表（§9.2 布局）
  - 卡片：名称、描述、文档数 / chunk 数统计、操作按钮（上传 / 重新索引全部 / 删除）
  - 新建知识库：弹窗表单（名称 + 描述）
- [x] `src/components/DocumentUpload.vue`：
  - `el-upload` 拖拽/选择上传，白名单校验（pdf/md/txt/docx）+ 大小限制（50MB，前后端一致）
  - 上传后轮询文档状态：`processing → ready / failed`（失败展示 error_message）
- [x] 文档列表（库详情视图）：文件名、chunk 数、状态标签、操作（删除 / 重新索引）—— 重新索引接口 Phase 3-05 提供
- [x] 删除确认：Element Plus `MessageBox` 二次确认；**删除知识库要求输入名称确认**（防呆）
- [x] 统计信息栏（§9.2）：文档数 · chunk 数 · 向量维度（1024），数据来自 `/api/stats` 与库详情
- [x] 与 ChatView 联动：侧边栏知识库列表共用 Pinia store（`knowledgeBases.ts`），管理界面改动后聊天界面同步刷新
- [x] 路由：`/knowledge-bases` 页面 + 侧边栏入口

## 3. 设计要点

- **状态轮询**：文档处理是异步任务（Phase 2-02），前端轮询（2s 间隔）直到状态非 `processing`；轮询在组件卸载时清理
- **上传即入库**：上传成功后自动轮询，不要求用户手动刷新
- **删除防呆**：文档删除用普通确认框；知识库删除（级联删向量库，不可恢复）用「输入知识库名称」确认，防止误触
- **失败可见**：`failed` 状态展示 `error_message`（解析失败原因等），用户能理解并重试
- 与 §9.2 的展示差异记录：设计文档的统计是静态示意，实际以接口数据为准（`/api/stats`）

## 6. 风险与注意事项

- **轮询频率**：2s 一次对后台任务够用；大文档处理时间长，轮询期间要有 loading 视觉反馈
- **接口契约**：文档状态字段（`status`）与错误信息（`error_message`）是前后端契约，Phase 2-02 已定，前端按此实现，变更需同步
- **上传并发**：同一库同时上传多文件时，前端按文件逐个轮询；后端串行处理（Phase 2-02 的写入锁），界面展示各文件独立状态
- 管理界面与聊天界面共用知识库数据，注意 Pinia store 的单向更新（管理页修改 → store 更新 → 聊天页响应）
