# Phase 1 · 01 项目初始化 — 开发文档

> **所属阶段**：Phase 1 — MVP（最小可用版本）
> **路线图条目**：§11 Phase 1 第 1 项「项目初始化」
> **参考章节**：§3 技术栈 · §10 项目目录结构 · §12 环境变量配置
> **前置依赖**：无（本项目第一步）
> **状态**：待开发

## 1. 目标与范围

搭建项目骨架，建立与设计文档 §10 一致的目录结构，完成工程化基础（包管理、gitignore、环境变量模板、README），使后续每一步开发都有可落地的载体。

**范围**：仅项目骨架，不含任何业务代码。

## 2. 任务拆解

- [ ] 初始化 git 仓库，确认分支规范（`main` + 功能分支 `feature/*`）
- [ ] 按 §10 创建目录结构：
  - `backend/app/{api,core,memory,llm,store,models}` + `backend/tests`
  - `frontend/src/{views,components,stores,api,router}`
  - `docs/`、`data/`（含 `chroma/`、`uploads/`）
- [ ] Python 包管理初始化（uv 或 pip），创建 `backend/requirements.txt` 基础占位
- [ ] `.gitignore`：忽略 `data/`、`.env`、`__pycache__/`、`.venv/`、`node_modules/`、`dist/`、`.idea/`
- [ ] `.env.example`：按 §12 提供全部环境变量模板（含注释说明）
- [ ] `README.md`：项目简介、目录说明、启动方式占位
- [ ] 首轮 git 提交（只提交骨架，不含运行时数据）

## 3. 设计要点

- 目录结构严格对齐 §10，后续所有开发文档中的「涉及文件」均以它为根；**一旦定下不轻易改名**（与 Python import 路径、前端别名强耦合）
- `data/` 是运行时目录（向量库、上传文件、SQLite 均在其下），必须 gitignore；服务启动时自动创建缺失目录
- `.env` 不入库，`.env.example` 入库；密钥类配置只写占位符
- `backend/` 与 `frontend/` 各自独立的包管理（后端 uv/pip，前端 npm），互不依赖

## 5. 验收标准

- [ ] 目录结构与 §10 一致（`data/` 子目录由启动脚本自动创建也可）
- [ ] `uv sync`（或 `pip install -r requirements.txt`）可正常执行
- [ ] `git status` 干净：`data/`、`.env`、`.idea/` 未被 git 跟踪
- [ ] `.env.example` 包含 §12 的全部键，且带注释说明

## 6. 风险与注意事项

- **目录改名成本**：结构一旦使用即与 import 耦合，变动会波及所有文件，务必在一开始就对齐 §10
- **.env 泄露**：检查 `.gitignore` 是否覆盖 `.env` 与 `*.env.local`，防止密钥入库
- git 用户信息已配置（`a-little-xiaoyu`），提交前确认邮箱与远端一致
