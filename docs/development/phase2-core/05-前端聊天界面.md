## 3. 设计要点

- **SSE 用 fetch 流而非 EventSource**：EventSource 无法携带自定义 header、无法主动中止；fetch + `response.body.getReader()` 解析 `event:`/`data:` 行（后端协议见 Phase 2-01），或直接用 `text/event-stream` 解析器
- **引用格式解析**：`[来源: 文件名 P页码]` 正则提取 → 点击展开该来源的 snippet（后端 done 帧的 `sources` 字段为准，正文标注只做展示）
- **状态管理**：消息数组是唯一数据源，流式 delta 只追加当前流；切换会话时清空流式状态
- **知识库选择器**：未选知识库时发送按钮禁用并提示；默认选中第一个
- 会话持久化：会话列表来自后端；刷新页面后重新拉取，当前会话按 id 恢复（浏览器不存消息副本）

## 6. 风险与注意事项

- **流式解析兼容性**：不同后端实现 SSE 帧格式略有差异，解析器按 Phase 2-01 协议严格实现，前后端联调一次定死
- **长回答渲染性能**：delta 高频追加时用批量渲染（requestAnimationFrame 或手动节流），避免每 token 触发一次 DOM 更新
- **CORS**：开发环境后端已放行 `localhost:5173`（Phase 1-02）；生产部署跨域由同源 nginx 解决（Phase 4）
- 打字机效果依赖后端增量粒度：若后端一次推一大段，前端效果退化（后端流式每帧 ≤ 几十字符时体验最佳）
